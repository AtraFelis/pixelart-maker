## 작업 순서

1. 생성 연결 프로필을 선택하고 실제 서버·모델·노드를 확인. VRAM은 실제 생성 대상 기준으로 판단.
2. 시제품의 런타임·패키지 도구·버전을 선택하고 결정 근거 갱신.
3. 기본 픽셀 처리와 규격 검사를 작은 입력으로 검증.
4. MCP 어댑터와 실제 워크플로를 연결.
5. 빨간 물약 한 개로 생성부터 PNG 재열기까지 실행.
6. 기준선과 격자 복원 후보를 비교. 추가 의존성·모델이 필요하면 근거와 범위를 기록.
7. 6개 대표 소재를 평가하고 다음 개발의 모델·처리 구성을 제안.
8. 설치·실행·검사 명령과 실제 결과 기록.

## 검증 계획

- AC-02·03·08: PNG 왕복, 크기·색상·알파와 한글 경로의 자동 검사.
- AC-04·05: 도구 응답과 상태 변화의 자동 검사 및 실제 MCP 실행.

정확한 명령은 런타임·실행 진입점 구현과 함께 등록한다. 아직 없는 명령이나 성공하는 빈 검사를 추가하지 않는다. 실패 검사는 원인을 확인하며, 테스트를 약화해 결과를 맞추지 않는다.

## 위험과 대안

- 처음부터 전체 UI를 만드는 대안은 핵심 품질이 확인되지 않아 뒤로 미룬다.
- 모든 후처리를 ComfyUI 노드로 구성하는 대안은 필수가 아니다. CPU 코드와 외부 도구를 병행할 수 있다.
- 무조건 8배 축소하는 대안은 모델·입력별 격자 차이와 최종 크기 차이 때문에 기준선으로만 사용.
- 모델·노드 변경은 기존 환경에 영향을 주므로 필요성·호환성과 작업 범위를 확인한다.
- 타임아웃은 실패와 구분하고, 접수 여부 확인 전에 요청을 다시 보내지 않는다.

## 배포와 되돌리기

외부 배포·DB 마이그레이션 없음. 새 코드를 복구할 때도 생성 원본과 사용자 데이터는 보존한다. 기존 ComfyUI 전체 업데이트·재설치는 이번 계획에 포함하지 않는다.

## 2026년 10월 31일 구현 수락과 기술 선택

사용자가 Python 명령줄 시제품의 설명을 확인한 뒤 “좋아. 진행해줘.”라고 요청했다. 생성·변환·저장·보고서와 6개 소재 평가 범위를 구현한다.

Python 3.11~3.13, uv와 잠금 파일, Pillow·NumPy·MCP Python SDK 1.x를 사용한다. 초기 연결은 로컬 MCP이며 공급자 계약과 원격 자체 운영 ComfyUI HTTP 어댑터를 분리한다. 관리형 클라우드 인증·실제 다른 PC는 미검증 범위로 남긴다. 표준 unittest를 사용하며 CLI·워크플로·요청·파일 저장·픽셀 변환·오류 복구를 검증한다. 전체 UI·모델 다운로드·노드 설치·배포는 수행하지 않는다.

## 구현 중 구체화

- 외부 격자 라이브러리·전용 모델 설치는 하지 않았으며 현재 비교의 한계로 명시.
