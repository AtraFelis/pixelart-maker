# 첫 시제품 샘플 평가

날짜: 2026년 10월 31일
평가자: 구현 에이전트의 자체 시각 점검. 사용자·독립 평가자의 판정은 아님.

## 실행 조건과 자동 검사

기존 Illustrious-XL-v2.0.safetensors, 코어 노드만 사용했다. 생성은 1024×1024, Euler ancestral 28 steps, normal, CFG 7이다. 프롬프트·시드는 examples/samples.json과 각 프로젝트의 request·workflow에 남겼다.

output/evaluation 아래 여섯 프로젝트를 생성하고 마지막 처리 코드로 원본을 다시 처리했다. 물약·사과·동전·열쇠는 32×32, 검·상자는 64×64다. 여섯 결과의 최근접·다수결 후보 모두 크기·최대 16색·이진 알파·PNG 왕복 검사를 통과했다.

실험적 격자 후보는 여섯 생성물 모두에서 충분한 주기적 경계를 검출하지 못해 만들지 않았다. 검출 실패를 성공으로 바꾸거나 임의 격자를 강제하지 않았다. 별도 합성 8배 확대 입력은 원래 32×32 RGBA로 정확히 복원됨을 자동 검사했다.

마지막 실행에서 후처리는 소재별 약 0.80~0.90초였다. 이 PC에서의 관찰이며 다른 PC의 성능 보장은 아니다. GPU 생성 시간은 별도 계측하지 않았다.

## 실제 크기와 확대본 관찰

### 물약 — 32×32, 16색

빨간 액체와 병·마개를 구분할 수 있다. 다수결 후보는 큰 색 면이 정리되고 최근접 후보는 작은 하이라이트가 더 남는다. 유리의 파란 윤곽과 마개 비율은 사용자 취향에 따라 다듬을 여지가 있다.

### 사과 — 32×32, 16색

빨간 몸체·줄기·잎으로 대상이 읽힌다. 몸체의 불필요한 녹색 점과 어두운 윤곽은 수작업 수정 후보다.

### 동전 — 32×32, 14색

노란 별처럼 생성되어 원형 동전이라는 요청을 충족하지 못했다. 규격은 통과하지만 내용은 실패한 사례다. 후처리만으로 원형 동전을 복원할 수 없다.

### 검 — 64×64, 16색

생성 원본에 검을 든 인물과 다른 캐릭터가 함께 들어왔다. 단일 무기 요청을 충족하지 못한다. 작은 크기에서 검과 사람의 검은 실루엣이 합쳐져 가독성도 낮다. 모델·생성 조건 개선이 필요하다.

### 상자 — 64×64, 16색

상자 형태와 입체적인 면은 구분된다. 닫힌 상자 요청과 달리 열린 형태가 나왔고 세부 장식은 거칠다. 사용 가능한 방향을 검토할 수 있지만 요청 완전 일치로 평가하지 않는다.

### 열쇠 — 32×32, 16색

고리·자루·이빨과 대각선 방향을 읽을 수 있다. 밝은 색 점이 많고 이빨은 작은 크기에서 정리가 필요하다. 두 변환 모두 비교할 가치가 있다.

## 첫 실패 샘플과 바뀐 조건

output/potion-32의 첫 실험은 768×768, 24 steps, CFG 5에서 UI 프레임·배경이 섞인 원본이 나왔다. 모서리 색이 달라 배경 제거를 건너뛰었고, 최종 크기로 줄였을 때 소재를 읽기 어려웠다.

생성 프롬프트·해상도·CFG·시드를 함께 바꾼 output/potion-refined에서 독립된 흰 배경 물약을 얻었다. 여러 요인이 달라 개별 변경의 인과 효과를 입증한 비교 실험은 아니다. 첫 실패 원본도 삭제하지 않았다.

## 다음 개발을 위한 판단

현재 시제품은 생성·수집·픽셀 변환과 규격 확인을 반복할 수 있는 도구다. 모든 요청에서 완성도 높은 소재를 자동으로 보장하는 단계는 아니다.

다음 품질 비교에서는 픽셀 전용 생성 모델·LoRA, 더 적합한 소재 프롬프트, 배경 마스크와 의미 있는 실루엣 보존을 검토한다. 현재 단계에서 새 모델·외부 격자 라이브러리는 설치하지 않았다. 사용자 미감 평가와 완성까지의 수작업 시간도 아직 측정하지 않았다.
