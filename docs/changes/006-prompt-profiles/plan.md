## 이번 문서 작업

1. 기존 개발 계획·변경 기록·실제 워크플로를 검색해 명시된 후속 작업이 없음을 확인한다.
2. 006의 intent·spec·plan·evidence에 현상·범위·우선순위와 후속 기준을 기록한다.
3. README·docs/project.md·전체 개발 계획에 알려진 문제와 006 링크를 추가한다.
4. 로컬 Markdown 링크·UTF-8·미입력 항목·공백·변경 범위를 검사한다. 문서 작업에 불필요한 앱 테스트·GPU 생성은 하지 않는다.
5. PR 전 CodeRabbit 검토 결과와 타당한 보완을 기록하고 main 대상 문서 PR로 제출한다. 자동 병합은 하지 않는다.

## 다음 구현 변경에서 수행할 일

이 알려진 문제를 다음 생성 기능 작업에서 우선 검토한다. 먼저 build_workflow의 실효 포지티브에 single isolated object가, 네거티브에 human·person·body·face 등의 조건이 포함되는지 결정적 회귀 검사로 확인한다. 수정 전에는 원치 않는 조건 때문에 실패하고 수정 후에는 같은 단언이 통과해야 한다. 실제 이미지의 자세·특징 평가는 spec.md의 별도 표현 평가로 유지한다. 이후 Request·CLI·워크플로·프리셋·저장·비교 스키마의 적용 순서와 호환성을 정하고, 공통 기본값과 소재별 설정을 분리한다. 같은 회귀 검사, 전체 테스트·빌드·CI, 아이템/캐릭터의 실제 생성 비교를 수행한다. 구현 전 이 문서의 제안 기준을 실제 변경 계획으로 구체화한다.

## 위험과 되돌리기

가장 큰 위험은 기록만 추가한 상태를 기능 수정 완료로 오해하는 것이다. 모든 진입 문서에 미구현 상태를 명시한다. 문서 변경을 되돌릴 수 있으며 앱·모델·사용자 프로젝트에는 변경이 없다. 과거 평가 증거와 사용자 원본은 보존한다.
