- DOC-03: README·프로젝트 기록·전체 개발 계획에서 후속 작업을 찾을 수 있다.

## 후속 앱 수정의 제안 기준 — 아직 미구현

1. 공통 기본값은 인물·사물 같은 소재를 임의로 억제하지 않는다. human·person·body·face 등 아이템 특화 억제와 single isolated object 같은 소재별 강제 조건은 명시적으로 선택한 프리셋에 둔다. scenery·room·architecture 등도 소재별 조건인지 함께 점검한다.
2. 공통·아이템·캐릭터 설정을 구분하며 아이템 프리셋을 프로그램 전체 기본값으로 조용히 적용하지 않는다. 프리셋은 보조 수단이고 사용자의 요청을 우선한다.
3. 사용자가 실제 포지티브·네거티브를 확인하고 수정할 수 있다. 프리셋과 사용자 입력의 적용·대체 순서를 명시한다. CLI 옵션 이름과 UI는 구현 명세에서 확정하며 현재 사용 가능한 기능으로 안내하지 않는다.
4. 선택한 프리셋·버전, 사용자 입력과 실제 적용된 프롬프트를 저장해 다른 PC·대상 서버에서도 생성 의도를 재현할 수 있게 한다. 워크플로의 실제 텍스트와 기록이 일치해야 한다.
5. 기존 프로젝트 재개는 저장된 워크플로·프롬프트를 보존하며 기본값 변경을 이유로 새로 제출하지 않는다. 예전 요청의 새 필드 누락 처리도 구현 시 명시한다.
6. 모델 비교에서는 같은 요청의 실효 프롬프트가 변형별로 달라지지 않도록 한다. 새 필드는 명시적 스키마로 허용하며 비교 정의의 임의 덮어쓰기 방지를 유지한다.
7. 알 수 없는 프리셋·잘못된 설정은 제출 전에 거절한다. 공통/캐릭터 설정이 인물 억제 조건을 자동 삽입하지 않는지 회귀 검사한다.

## 후속 표현 평가

기존 여섯 아이템과 사용자 여성 기사 요청을 함께 평가한다. 기사 요청은 64픽셀의 실루엣·금발·갑옷·칼끝 방향·경례 자세를 별도로 확인한다. 프롬프트 충돌 해소와 모델의 자세·특징 준수는 구별하며, 자동 규격 검사만으로 표현 성공을 선언하지 않는다. 이미지 생성과 모델 호환성 확인은 실제 구현 단계에서 실행한다.
