# Spec: 픽셀아트 프로젝트 초기 구성

- 변경 ID: 000-project-bootstrap
- 입력: [intent.md](intent.md)
- 상태: 사용자 요청 범위에 맞춰 구성

## 요구사항과 설계

- 템플릿의 AGENTS·CLAUDE·REVIEW와 개발 문서 구조를 적용한다.
- README는 제품 소개와 현재 상태, 문서 진입점으로 바꾼다.
- project에는 사용자 요구, 제안, 수락·구현 상태를 구분한다.
- workflow·verification·release는 개인용 로컬 프로젝트의 현재 단계에 맞춘다.
- TEMPLATE는 재사용 양식으로 유지하고 000과 001을 별도 작성한다.
- .gitignore에 로컬 데이터·모델·자격증명·언어별 캐시와 빌드 산출물을 등록한다.
- 원격 없이도 선택적으로 사용할 PR 양식만 복사한다.
- 플레이북의 관련 원칙과 실제 적용 범위를 참고 문서에 남긴다.

## 수용 기준

- AC-01: 기존 두 조사·계획 문서가 내용 변경 없이 남아 있다.
- AC-02: 템플릿 공통 파일과 네 종류 변경 양식이 존재한다.
- AC-03: 제품 정의, 절차, 검증과 첫 구현 준비 문서가 연결되어 있다.
- AC-04: 실제 상태와 승인 범위를 구분하고 거짓 실행·승인 기록이 없다.
- AC-05: 로컬 산출물 제외 규칙이 적용되고 .env.example은 제외하지 않는다.
- AC-06: 문서 링크와 UTF-8 텍스트, 새 파일 공백 검사가 통과한다.
- AC-07: 원본 템플릿·PDF·.git 설정을 변경하지 않는다.

## 위험과 처리

기존 문서 덮어쓰기, 템플릿의 미정 값이 실제 결정으로 오인되는 문제, 첫 커밋 전 파일이 검증에서 빠지는 문제를 방지한다.

원본 템플릿의 파일과 기존 문서는 별도로 보존하고, 미추적 파일까지 검사한다. 앱에 적용할 도구가 아직 없으므로 문서 검사만 수행하고 앱 검증으로 확대하지 않는다.

## 수락 기록

사용자의 초기 구성 요청으로 이 범위의 문서 작업을 수행한다. 별도 설계 승인이나 독립 검토가 있었다고 기록하지 않는다.
