# Spec: 캔버스·생성·확대 크기 분리

1. 픽셀 캔버스는 각 변 32..2048의 정수다. --size N은 정사각형, --width W --height H는 직사각형이다. 한 쌍이 모두 필요하고 CLI에서 --size와 혼용을 거절한다. 기본 32, 기존 32·64와 Python 위치 인자 사용은 유지한다. Python Request에서 width/height를 주면 기본 size=32를 대체해 size=None으로 저장하며 명시적인 다른 size와의 혼용은 거절한다.
2. --export-scale 1..16의 정수 배율을 적용한 export.png를 별도 저장한다. 각 변 최대 8192, 총 16,777,216픽셀을 넘으면 처리/연결 전에 거절한다. final.png·candidates는 픽셀 작업 크기이며 export는 nearest 정수 확대다. 모든 RGBA 픽셀이 정확한 배율 블록을 이루는지 자동 검사한다. 배율 1도 별도 export 자산을 제공한다.
3. ComfyUI 생성은 기존 --generation-size 512/768/1024를 유지하고 --generation-width/--generation-height를 추가한다. 한 쌍·각 변 256..2048·64 배수·총 1,048,576픽셀 이하만 허용한다. CLI에서 정사각형 옵션과 혼용을 거절한다. 새 Request의 명시적 쌍은 기본 generation_size=1024를 대체해 None으로 저장한다. 코어 노드의 실제 폭/높이에 반영하고 서버에서 매 그래프를 검증한다. VRAM·모델의 구도 준수는 별도 실제 검증이며 임의 대형 GPU 작업·타일 생성을 숨겨 실행하지 않는다.
4. 기존 비율 유지·중앙 배치·padding과 세 후보 처리를 직사각형에 적용한다. padding은 짧은 변 기준으로 검증한다. 배경·팔레트·알파 규칙은 유지한다. 원본보다 큰 출력은 업스케일임을 보고서에 알리며 새로운 세부 복원을 주장하지 않는다.
5. 미리보기는 max(1, min(16, 1024 // 긴 변))의 정수 배율로 제한한다. 32/64의 16배 파일명·RGBA는 유지하고 큰 캔버스에서 거대 16배 PNG를 만들지 않는다. 원본보다 축소하는 미리보기는 만들지 않는다. 실제 배율·작업/생성/내보내기 크기를 report와 inspect에 표시한다.
6. 큰 캔버스의 다수결 확대는 기존 셀 투표와 같은 좌표·알파 동작을 유지하는 벡터 경로를 사용한다. 큰 네이티브 출력의 무의미한 픽셀별 Python 반복을 피한다. 다운샘플링 투표 동작은 바꾸지 않는다.
7. 새 필드가 없는 예전 프로젝트는 예전 크기와 export_scale=1로 연다. 재개 시 저장 워크플로·원본·job_id를 보존하고 재제출하지 않는다. 추가 export/report는 재처리 출력이다. 비교의 width/height는 샘플에, 생성 크기와 export_scale은 공유 설정에만 허용하며 임의 변형별 덮어쓰기는 계속 거절한다. 동일 기본 설정의 예전 v1/v2 비교와 기존 18개 완료 결과의 재사용은 유지한다.
8. 입력 한도·잘못된 정수/쌍/혼용·최대 메모리 요청·예전 요청·복구·PNG 재열기·정수 블록 동일성·진짜 CLI를 검사한다. 규격과 표현 평가는 구별한다. 기존 여성 기사 원본의 여러 크기와 새 가로형 로컬 생성의 native/export를 실제 확인한다. 부분 그림·전체 스타일 일관성은 후속 범위다.
