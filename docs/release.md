# 배포와 되돌리기

현재 외부 배포·앱 패키지·릴리스 파이프라인은 없다. 문서 초기 구성은 운영 배포가 아니다.

## 첫 로컬 실행 전

- 앱 설치·실행·검증 명령이 실제 환경에서 확인됐는지.
- 연결할 ComfyUI 주소와 모델·입출력 경로가 의도한 대상인지.
- 사용자 데이터와 설정이 소스·산출물과 분리되는지.
- 유료 API나 모델·노드 설치가 실행 흐름에 숨어 있지 않은지.
- 중단·재시도·프로젝트 저장과 재열기가 가능한지.

## 배포 기록 양식

- 변경 ID / 버전 / 대상 환경:
- 담당자 / 승인 범위와 근거:
- 배포 명령과 실제 결과:
- 핵심 흐름·로그 확인:
- 되돌릴 조건과 절차:
- 프로젝트 파일·DB 형식의 호환성:
- 데이터 보존·백업 및 복구 확인:
- 미검증 범위:

외부 배포와 파괴적 데이터 작업은 해당 작업의 권한을 확인한다. 구체적인 배포물이 생기면 실제 절차를 등록하며, 아직 없는 롤백 명령을 성공했다고 기록하지 않는다.

문서 구성을 되돌릴 때는 해당 변경의 파일만 선택적으로 복구하며, 유지 중인 개발 문서·.git·사용자 데이터와 원본 템플릿을 보존한다. 사용자가 삭제한 선택적 참고 파일을 자동 복원하지 않는다.
