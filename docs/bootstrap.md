# 새 프로젝트 복사본 초기화

## 이 프로젝트의 적용 상태

2026년 10월 31일 사용자의 템플릿 적용 요청에 따라 구성했습니다. [초기 구성 기록](changes/000-project-bootstrap/evidence.md)과 [프로젝트 정의](project.md)가 현재 상태의 기준입니다.

제품 방향·검증 절차·공통 규칙과 첫 시제품 초안을 준비했습니다. 첫 구현 계획 수락, 앱 설치·실행·테스트와 외부 배포는 별도 단계입니다. 아래 목록은 재사용 절차이며 미체크 항목을 실제 구현 완료로 취급하지 않습니다.

이 안내는 새 프로젝트로 복사한 폴더에서 사용합니다. 원본 템플릿을 관리하는 동안에는 실행하지 않습니다.

## 1. 복사와 보존
원본의 공통 문서와 숨김 파일을 새 폴더에 복사합니다. 원본 저장소의 `.git`, 로컬 자격증명, 캐시, 산출물은 가져오지 않습니다. Git 저장소 생성·원격 연결은 프로젝트 작업 범위에 맞춰 별도로 수행합니다. 기존 프로젝트에 적용할 때는 AGENTS.md·CLAUDE.md·README·.gitignore 등 기존 설정을 먼저 읽고 병합합니다.

## 2. 제품부터 결정
사용자의 설명으로 `docs/project.md`와 첫 변경의 intent를 작성합니다. 프로젝트 유형, 대상 플랫폼, 성공 기준, 외부 연동, 데이터 제약을 정리합니다. 이미 알려진 내용은 다시 묻지 않고, 설계 판단을 바꾸는 누락 정보만 확인합니다.

## 3. 기술과 절차 선택
요구사항과 기존 환경을 근거로 기술 스택을 제안합니다. 선택 이유와 제약을 spec에 남기고, 확정된 것만 project에 반영합니다. 언어·프레임워크·폴더 구조·패키지 관리자를 템플릿이 대신 결정하지 않습니다.

- 개인 프로젝트: 소유자가 제품·기술·릴리스 역할을 겸할 수 있습니다.
- 팀 프로젝트: 실제 책임자와 검토·승인 경로를 지정합니다.
- GitHub 사용: PR 템플릿을 프로젝트에 맞게 편집합니다.
- 다른 저장소 서비스 또는 PR 미사용: PR 양식 내용을 해당 리뷰 도구·변경 기록에 옮기고 `.github/`는 생략할 수 있습니다.
- Claude 사용: CLAUDE.md가 AGENTS.md를 읽는 진입점입니다.
- 다른 AI 도구 사용: 도구가 지원하는 진입점으로 AGENTS.md를 연결하고 실제 로딩을 확인합니다. 지원 여부를 추정하지 않습니다. CLAUDE.md는 생략할 수 있습니다.

## 4. 첫 구현 준비
첫 변경 폴더에 intent·spec·plan을 작성하고 검토합니다. 테스트, 실행 명령, 필요한 권한과 릴리스 방식을 정합니다. 최초 앱 골격 자체를 구현하는 작업은 검증 도구가 아직 없을 수 있으므로, plan에 도구 구성과 최초 검증을 포함하고 구현 후 실제 실행합니다.

## 5. 복사본 완료 확인
- [ ] project 상태를 템플릿에서 준비 중으로 변경
- [ ] 제품·플랫폼·범위·책임자 기록
- [ ] 첫 변경의 수용 기준·계획과 수락 근거 기록
- [ ] 적용할 검사와 적용하지 않는 검사의 이유 결정
- [ ] 도구별 규칙 진입점과 필요한 리뷰 양식 선택
- [ ] 복사본 README를 제품 소개·설치·실행·검증 안내로 변경
- [ ] 언어별 .gitignore를 실제 스택에 맞춰 보완

초기화 완료는 제품 구현이나 테스트 통과를 뜻하지 않습니다. 이후 작업은 docs/workflow.md를 따릅니다. 원본에 반영할 개선은 제품별 값이 없는 공통 절차·양식으로만 환원합니다.
