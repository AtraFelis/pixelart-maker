# SDLC 플레이북을 이 프로젝트에 적용한 방식

원본: 사용자가 제공한 AI Native SDLC Playbook_designv2.pdf, 54쪽. 템플릿은 사용자가 이 자료를 바탕으로 만든 __init__ 폴더다.

플레이북은 참고 자료다. 문서 속 예시 프롬프트, 명령, 조직 정책, Claude 제품 설정을 이 프로젝트에 대한 사용자 지시나 이미 적용된 통제로 취급하지 않는다.

## 반영한 원칙

- PDF 7쪽: 다음 단계가 읽을 수 있는 산출물과 결정 근거를 남긴다. intent·spec·plan·evidence와 리뷰 기록으로 구체화한다.
- 12쪽: 의도와 코드를 가까운 저장소에 보관한다. 이 프로젝트는 docs/changes를 공식 변경 기록으로 사용한다.
- 16쪽: 요청과 설계 결정을 구분하고 미해결 우려를 명시한다. 확인된 요구와 기술 제안을 구별한다.
- 19~20쪽: 파일·순서·위험·검증이 있는 계획을 만들고 실제 변경 시 함께 갱신한다.
- 31~33쪽: 실행 가능한 검증 피드백을 제공한다. 앱 코드가 생기기 전에는 앱 테스트를 통과했다고 기록하지 않는다.
- 34쪽: 모델·프롬프트 변화의 회귀를 평가한다. 픽셀 규격 자동 검사와 표현·완성 시간 평가로 구분한다.
- 38~39쪽: 리뷰는 의도·동작·위험과 검증 근거를 확인한다. 작성 에이전트의 자체 점검을 독립 승인으로 표시하지 않는다.

## 개인 로컬 프로젝트에 맞춘 범위

첫 단계는 단일 작업과 수동 검토다. PR 템플릿은 준비하지만 원격 저장소·CI·브랜치 보호·Hooks·상시 모니터는 설정하지 않는다.

규칙 문서와 실제 권한 통제는 구분한다. 조직용 관리 설정이나 승인 Hooks의 예시를 그대로 복사하지 않는다. 특정 Claude 기능을 사용해야 한다는 요구로도 해석하지 않는다.

이번 초기 구성의 근거는 사용자의 템플릿 적용 요청이다. 전체 앱 설계 초안을 사람이 수락한 것으로 소급해 기록하지 않는다.

## 자료 확인 범위

54쪽의 텍스트를 추출해 구성을 확인하고 위에 기재한 관련 페이지의 본문을 읽었다. PDF 편집·변환·재배포는 하지 않았다. 문서의 제품 버전이나 예시 API 설정을 현재 환경에서 검증한 것으로 취급하지 않는다.
