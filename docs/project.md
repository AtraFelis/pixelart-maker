## 사용자 요구로 확인된 방향

- 제품명: AI 픽셀아트 제작 프로그램. 별도 브랜드명은 미정.
- 사용자와 문제: AI 이미지의 불규칙한 격자, 과도한 색상, 작은 크기에서의 특징 손실과 수정 부담을 줄이려는 제작자.
- 생성 기본 연동: ComfyUI MCP.
- 다른 프로그램·코드·MCP를 전후 처리에 사용할 수 있다.
- 결과적으로 제대로 된 픽셀아트가 나오는 것이 우선이다.
- 다른 PC로 프로그램과 프로젝트를 옮길 수 있어야 하며, 생성 위치는 로컬·다른 PC·클라우드에서 선택할 수 있어야 한다.
- 현재 요청 범위: Python CLI 시제품의 생성·픽셀 변환·저장·보고서와 실제 샘플 검증.
- 책임자: 프로젝트 소유자인 사용자. AI는 구현·자체 점검을 지원하며 독립 승인자를 자처하지 않는다.

근거: 이 채팅의 프로그램 계획 요청, 도구 조합 허용 설명, 템플릿 적용 요청과 PC 이동·클라우드 생성 요구.

## 기술과 범위 제안

다음은 기존 계획에서 옮긴 제안이며 앱 구현 승인과 구분한다.

- 프로젝트 유형: 다른 PC로 이동 가능한 개인용 프로그램. 첫 확인 환경은 Windows, 초기 UI는 로컬 브라우저. 실제 생성은 로컬 또는 원격에서 실행.
- 첫 대상: 32×32·64×64 정적 아이콘과 오브젝트.
- UI 후보: TypeScript + Canvas 2D.
- 작업·이미지 처리: Python.
- 메타데이터 저장: SQLite, 원본·결과는 프로젝트 파일.
- 생성 연결: 자체 MCP 클라이언트와 공급자 어댑터. 로컬 MCP·원격 자체 운영 ComfyUI·관리형 클라우드를 구분하며 실제 기능·인증을 조회.
- 후처리 후보: 기본 재샘플링, Pixel Art Fixer, Perfect Pixel.
- 선택적 편집기: 사용자 환경에 설치된 Aseprite.
- 구조: 단일 저장소. 코드 위치는 첫 spec·plan에서 제안하고 구현 시 확정.
- CLI 런타임: Python 3.12, uv·uv.lock, Pillow·NumPy·MCP SDK 1.x. 현재 Python 3.12.14에서 검사. HTTP 프레임워크와 UI 기술은 후속 단계에서 확정.
- 장기 기능: 소재 세트, 캐릭터 방향, 애니메이션, 타일셋.

## 성공 기준

- 규격: 실제 크기, 팔레트, 알파, PNG 재열기와 보호 영역 동일성.
- 표현: 실제 크기에서 실루엣, 특징, 윤곽선, 명암, 스타일을 평가.
- 생산성: 사용 가능한 소재 한 개까지 걸린 시간, 재생성과 수작업 수정량.
- 격자 정리가 미적 완성도를 자동으로 보장한다고 취급하지 않는다.
- 첫 구현은 앱 전체보다 생성부터 픽셀 결과까지의 작은 경로를 먼저 검증한다.

## 로컬 데이터와 설정

- data/: 로컬 프로젝트·참고 이미지·생성 원본·수정본·작업 DB.
- output/: 평가 보고서·내보내기 결과.
- models/: 모델을 이 저장소 안에 둘 경우의 로컬 경로. 기본은 기존 ComfyUI 모델 위치를 참조.
- .env 및 .env.local: 필요한 경우의 로컬 설정. 공유 예제에는 값 대신 설정 이름만 쓴다.
- 로컬 절대 경로와 실행 파일 경로는 코드에 고정하지 않는다.
- 이동용 프로젝트는 이미지·팔레트·이력·워크플로 명세를 상대 경로로 묶고, 머신 설정·인증·모델 가중치는 기본 제외한다. 상세 기준은 [실행 구조](architecture/execution.md)를 따른다.
- 사용자 이미지와 생성물은 자동 삭제하지 않는다. 보관·정리는 별도 기능으로 설계한다.
- 모델·이미지는 기본 Git 관리 대상에서 제외한다. 공개 가능한 소형 검증 이미지는 tests/fixtures 아래에 출처와 함께 별도로 관리할 수 있다.

## 실행과 외부 연결

- Python CLI 설치·실행 명령은 README와 docs/verification.md를 따른다. UI·인페인트·관리형 클라우드 연결은 미구현이다.
- ComfyUI 상태와 하드웨어 조회는 앞선 계획 작성 때의 스냅샷이다. 구현 실행 전 다시 확인한다.
- 로컬 편집 UI와 서비스는 초기에는 루프백 접속을 사용한다. 이는 생성 서버의 로컬·원격 선택과 별개다. 원격 생성의 인증·입출력 전송·대상 서버 의존성 검사를 어댑터에 둔다.
- 유료 생성, 모델 다운로드, 노드 설치·업데이트는 기본 실행에 숨겨 넣지 않는다. 필요할 때 작업 범위를 명시한다.
- 원격 저장소: origin = https://github.com/AtraFelis/pixelart-maker.git (사용자 요청으로 2026년 10월 31일 연결). 기본 브랜치: main. 빈 초기 커밋을 기준으로 작업 단위별 PR 제출. 최초 시제품은 codex/001-generation-spike 브랜치.
- .github/workflows/ci.yml로 PR·main push의 CPU 검사를 구성한다. 실제 실행 상태는 005 evidence를 따른다. PR 양식과 CodeRabbit 리뷰는 이 실행 검사와 별개이며 브랜치 보호는 아직 설정하지 않았다.
