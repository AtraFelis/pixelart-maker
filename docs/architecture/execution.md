# PC 이동과 생성 서버 선택

상태: 사용자 요구 반영, 구현 전 설계
갱신일: 2026년 10월 31일

## 지원할 사용 방식

- 같은 PC: 편집·후처리와 ComfyUI 생성을 같은 PC에서 실행.
- 다른 로컬 PC: 프로그램·프로젝트를 옮겨 그 PC의 ComfyUI 또는 원격 생성 서버에 연결.
- 다른 PC나 임대한 GPU 서버: 편집 앱은 사용자 PC에 두고 ComfyUI 생성만 다른 머신에서 실행.
- 관리형 클라우드: Comfy Cloud 등 서비스의 연결·인증·워크플로 기능에 맞는 어댑터로 생성.

첫 확인 환경은 Windows다. 다른 Windows PC로의 이동과 GPU가 없는 클라이언트에서의 원격 생성은 핵심 요구다. Linux·macOS용 앱 지원은 실제 설치·검증 후 지원 목록에 추가하며, 현재 호환을 보장하지 않는다.

웹사이트 공개, 여러 사용자의 동시 편집과 자동 동기화는 이 요구와 별도다.

## 분리할 세 가지 정보

1. 프로젝트: 픽셀 이미지·팔레트·규격·수정 이력·생성 요청·워크플로 명세.
2. 머신 설정: 로컬 실행 파일, 설치 위치, 캐시·데이터 저장 위치.
3. 생성 연결 프로필: 공급자 종류, 접속 주소, 인증 참조, 모델 매핑, 기능.

프로젝트는 특정 Windows 사용자명, 드라이브나 설치 경로에 의존하지 않는다. 내부 파일은 프로젝트 상대 경로와 자산 ID로 참조한다. 외부 참조 이미지는 이동용 프로젝트를 만들 때 포함하거나, 누락 목록을 제공한다.

새 PC에서는 머신 설정과 인증만 다시 연결하고 기존 이미지·팔레트·편집을 이어간다.

## 프로젝트 옮기기

이동용 묶음에는 버전이 있는 프로젝트 명세, 이미지·마스크·수정 이력, 팔레트, 워크플로와 모델 의존성 명세를 넣는다.

API 키·토큰·인증 세션·머신별 설정·불필요한 캐시는 넣지 않는다. 모델 가중치는 기본 포함하지 않고 이름·버전·확인 가능한 해시 등 식별자를 기록한다. 모델 설치나 공급자 권한은 별도로 확인한다.

SQLite를 쓰면 열린 DB 파일을 무작정 복사하지 않고 일관된 백업·내보내기를 제공한다. 첫 시제품은 JSON 명세와 파일로 이동 경로를 먼저 검증한다. 동기화 폴더의 동시 DB 쓰기를 지원한다고 가정하지 않는다.

대상 PC에서 자산을 다시 연결하고 검사한 뒤 열도록 한다. 누락된 모델은 재생성에 영향을 주지만 이미 저장한 이미지의 열기·편집을 막지 않는다.

## 생성 어댑터

핵심 로직은 공급자별 도구 이름을 직접 호출하지 않는다. 기능 조회, 의존성 확인, 입력 전송, 작업 제출·조회·취소, 결과 수집을 어댑터의 공통 책임으로 둔다.

- 로컬 MCP: 현재 연결된 comfy-mcp의 stdio와 도구 스키마 사용.
- 원격 자체 운영 ComfyUI: 선택한 서버를 실제로 조회·실행할 수 있는 MCP 또는 HTTP API 어댑터 사용.
- 관리형 클라우드: 해당 서비스의 원격 MCP 또는 API, 인증 방식과 작업·자산 식별자 사용.

로컬 MCP와 Comfy Cloud MCP는 서로 다른 연결이다. Comfy Cloud에는 호스팅 MCP가 있으며 로컬과 도구·인증을 동일하다고 가정하지 않는다. [공식 연결 안내](https://docs.comfy.org/agent-tools/mcp)

현재 comfy-mcp에는 원격 대상으로 전달되는 작업 기능과 로컬 설치를 조회하는 관리 기능의 차이가 있다. 원격 실행 전에 로컬 모델·VRAM·노드 조회를 원격 검증으로 사용하지 않는다. 서버 전체 기능이 주소 하나로 전환된다고 가정하지 않는다. [공식 로컬 MCP 저장소](https://github.com/Comfy-Org/comfy-mcp)

클라우드 모델·노드가 로컬 워크플로와 같다는 보장은 없다. 실행 전 실제 대상의 사용 가능한 기능과 의존성을 확인하고, 불일치는 필요한 매핑·대안과 함께 설명한다.

## 입력과 출력 이동

참고 이미지와 마스크는 실제 실행 대상이 읽을 수 있는 자산으로 전송한다. 사용자 PC의 절대 경로를 원격 노드에 전달하지 않는다.

서버별 자산 이름·ID와 로컬 자산 ID를 연결해 기록한다. 생성 결과는 확인 후 프로젝트에 내려받아 보관한다. 원격 임시 URL이 만료되어도 이미 완성한 작업을 열 수 있어야 한다.

중단된 전송·다운로드는 검증 후 재시도한다. 클라우드 결과를 받기 위해 같은 이미지를 다시 생성하는 방식으로 복구하지 않는다.

## 작업 추적과 서버 전환

작업에는 앱 작업 ID, 생성 연결 프로필 ID, 원격 작업 ID와 결과 수집 상태를 저장한다. ComfyUI의 prompt_id는 공급자별 작업 ID의 한 종류다.

제출한 작업은 원래 연결 대상으로 조회한다. 기본 서버를 바꾸어도 실행 중 작업의 소유 서버를 바꾸지 않는다. 가져온 프로젝트의 작업 기록에 접근 권한이 없으면 읽기 전용 이력으로 두고 완성 이미지 편집은 허용한다.

연결 실패나 GPU 부족 때 다른 서버로 자동 재제출하지 않는다. 특히 유료 클라우드로의 전환은 실행 위치·전송 파일·비용 조건을 사용자가 확인한 작업으로 남긴다.

로컬에서 편집·CPU 후처리·프로젝트 열기를 하는 데 로컬 CUDA가 필수는 아니다. GPU 요구량은 실제 생성 대상과 선택한 후처리 기능을 기준으로 판단한다.

## 개발과 검증 순서

첫 시제품부터 공급자 인터페이스, 상대 경로, 머신 설정 분리를 둔다. 현재 접근 가능한 로컬 서버로 첫 실제 생성 경로를 확인하되 이를 전체 지원 완료로 표시하지 않는다.

별도 검증에는 다음을 포함한다.

- 서로 다른 사용자명·드라이브·공백·한글 경로로 프로젝트 이동 후 열기·편집.
- GPU가 없는 클라이언트에서 프로젝트 열기·CPU 후처리와 원격 생성.
- 원격 서버의 모델·노드·인증 불일치 진단.
- 입력 업로드·원격 실행·결과 다운로드와 재연결 복구.
- 서버 전환 후 기존 작업을 올바른 서버에서 조회.
- 이동용 묶음에 자격증명·절대 경로가 포함되지 않는지 검사.
- 로컬과 원격 결과에 동일한 픽셀 규격 검사와 표현 평가 적용.

다른 실제 PC·원격 서버·클라우드 계정이 없는 항목은 미검증으로 기록한다. API 모의 검사를 실제 원격 동작이나 두 번째 PC 검증으로 대체하지 않는다.
